# data/ — изменяемые данные приложения

Каталог создан заранее, под целевое расположение рабочих данных:

```
data/
├── anpr.sqlite3        база проездов (SQLite, источник истины)
├── anpr_state.json     зеркало состояния (дни, seen, last_rec_no, reported_days)
├── subscribers.json    список чатов-получателей
├── ui_preferences.json настройки интерфейса
├── images/<дата>/      фотографии проездов
└── logs/               журналы сервиса (service.stdout.log, service.stderr.log)
```

## Сейчас здесь ничего нет

Рабочие данные намеренно **не перенесены**: миграция базы и фотографий
требует остановки сервиса и отдельного согласования (см. ниже). Пока
перенос не выполнен, приложение работает с файлами в корне проекта —
`anpr.sqlite3`, `anpr_state.json`, `subscribers.json`, `images/`,
`service.*.log` — ровно как работало до реорганизации.

## Порядок будущего переноса

1. Остановить сервис (панель управления → «Остановить»).
2. Сделать резервную копию: `anpr.sqlite3`, `anpr_state.json`,
   `subscribers.json`, `ui_preferences.json`, `.env` — вне рабочей папки.
3. Перенести файлы (не копировать) в `data/` по схеме выше.
4. Прописать в `.env` абсолютные пути: `DB_FILE`, `STATE_FILE`,
   `IMAGE_DIR`, `SUBSCRIBERS_FILE`.
5. Запустить сервис, сверить `python scripts/verify_state.py` (код 0)
   и число проездов в базе до и после переноса.

Перенос выполняется только при остановленном сервисе: работающая копия
базы (WAL) и копия файла разойдутся.

Содержимое `data/` в Git не попадает.
